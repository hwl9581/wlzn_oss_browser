# 1.0.5 S3 连接修复验证记录

日期：2026-10-28。

## 根因证据

用户安装 1.0.4 并重连后，真实 IDEA 日志记录 `ClassCastException`，调用链为 `javax.xml.stream.XMLInputFactory.newInstance` → AWS `XmlDomParser.createXmlInputFactory` → XML 响应解析。此时服务已返回响应，失败发生在插件内解析阶段。

安装包扫描发现 `stax-api-1.0-2.jar` 带有 `javax/xml/stream/XMLInputFactory.class`，`xpp3-1.1.4c.jar` 带有 `javax/xml/namespace/QName.class`，与 JDK `java.xml` 重复。Gradle 依赖链为：阿里云 OSS SDK → java-trace-api → aliyun-java-core → dom4j → 这两份可选 XML 依赖。

IDEA 插件优先加载会暴露重复 API 问题；独立 Java 和默认平台测试的父优先加载会掩盖问题，不能用独立测试通过证明 IDEA 内已修复。

## 修复和红绿回归

仅在阿里云 OSS SDK 依赖上排除 `javax.xml.stream:stax-api`、`xpp3:xpp3`，保留 dom4j、JDOM、JAXB 和两家 SDK 的其他依赖。现有 OSS 解析使用 JDOM SAXBuilder；xpp3 对应 dom4j 的可选 XPP3Reader，不在当前 OSS 功能调用链。

- 新增回归从实际插件 lib 载入依赖，以平台类加载器为父，对 XML API 模拟插件优先加载，再反射调用 AWS XmlDomParser 解析 S3 XML。
- 修复前失败：XMLInputFactory 预期来自模块 `java.xml`，实际为 unnamed module（null）。日志为本机临时文件 `wlzn-oss-xml-before.log`。
- 修复后 XMLInputFactory、QName 均来自 `java.xml`，AWS XML 响应解析通过。
- 全量 **54 个测试通过，0 failure / 0 error**，含 OSS/S3 官方 SDK 本机协议回归、错误诊断和 UI 状态测试。
- `test buildPlugin verifyPluginStructure verifyPlugin` 全部成功；最终 1.0.5 对 `IU-261.27258.48` 为 Compatible。
- 对最终 ZIP 内每个 JAR 再扫描：两份重复 XML 类为 0，stax-api/xpp3 旧 JAR 为 0。
- 真实 IDEA 验收通过：启动日志确认完整重启后加载 1.0.5；用户明确反馈“已重启，连接成功”。另只读核对 IDEA 界面显示已连接，且实际多级目录的对象列表加载成功。未进行真实云端写入。
- James 最终静态复查通过，已核对两个精确依赖排除、红绿回归、54 项测试报告及最终 ZIP 类扫描结果。

# 1.0.4 诊断验证记录

日期：2026-10-28。用户反馈 AWS S3 点击“连接”即出现 SdkClientException。

## 已确认事实

- 原始 Endpoint 为仅包含区域名的 AWS 域名，DNS 无法解析；正确 S3 东京服务域名可建立 HTTPS 连接。用户保存为正确地址后，IDEA 内仍报告客户端异常，不能把修正域名视为问题全部解决。
- 经用户明确授权，使用插件现有 `StorageClients`、AWS SDK 2.57.5 和本机 IDEA JBR 对其凭据执行真实只读验证：指定正确东京端点和留空自动路由均可列出 4 个 Bucket，并读取首个 Bucket 的对象列表（1 项）。
- 对齐 IDEA 的 JVM HTTP/HTTPS 代理参数、以及模拟 SDK 与线程上下文类加载器隔离后，同样通过。现有 PasswordSafe 原生条目的 AK/Secret 与用户提供值一致，无 Session Token。仅输出比对布尔值，凭据未写入源码、脚本、报告或日志。
- 上述验证未上传、删除、改权限或读取对象正文，也尚未复现真实 IDEA 进程中的异常链。其根因仍需安装诊断包后重连确认。

## 本版调整与回归

- 浏览连接、对象操作和目录树加载错误均记录有限 cause/suppressed 异常类型及代码栈帧，不传递 Throwable 给日志，不输出原始消息、凭据或请求正文。
- SDK 客户端错误按 DNS、TLS/证书、连接失败和超时显示安全提示；未识别的错误指向诊断日志。
- 只读失败/取消不再误报部分写入；建删 Bucket 及对象写入仍提醒核对已完成项，不改变原操作和重试次数。
- 配置保存时只拦截错误的纯 AWS 区域域名；保留自动端点、标准 S3、FIPS、dualstack 和兼容服务端点。
