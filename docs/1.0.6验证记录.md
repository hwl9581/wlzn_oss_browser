# 1.0.6 上传下载与路径栏修复

日期：2026-10-29。

## 用户反馈与处理

1. 面包屑路径被平均拉开：限定各路径按钮和分隔符最大尺寸，余下空间由末尾留白占用。宽窗口仍紧凑排列，父路径可点击导航。
2. 下载窗口文件名在深色主题下发黑：替换 Swing JFileChooser，上传/下载统一使用跟随 IDEA 主题的文件选择器；不新增自定义前景色。
3. 无重名也询问覆盖：先在后台完整规划任务，上传按准确对象 key 查询目标，下载按完整本地路径检查。仅真实同名文件集合非空时提示；已有目录、目录占位对象、无关文件不算覆盖冲突。
4. 选择下载目录后重复创建同名目录：改为选择已有目录，直接将该目录作为根路径。云端当前目录下的文件直接存入所选位置，所选子目录保留云端层级，不再拼接本地目录名。
5. 下载目录不记忆：独立持久保存上次确认的下载目录；已删除时回退最近的现存父目录。
6. 上传目录不记忆：独立保存上传文件所在目录或选中的上传目录，支持多文件/目录选择及拖放；不与下载目录相互覆盖。

目录记忆复用现有非漫游应用状态，旧状态缺少新字段时仍可加载。未修改云端凭据、连接配置、品牌图标或已有传输断点格式。

## 覆盖与路径保护

- 选择覆盖只授予预检时发生冲突的文件任务；其他任务保持禁止覆盖。预检后新出现的同名文件仍由原传输引擎保护/跳过。
- 本地目录与云端文件同名、文件阻挡目标父目录等情况，在规划阶段拒绝，不尝试删除目录。
- OSS/S3 允许同时存在 `photos` 和 `photos/a.jpg`；本地无法同时将 `photos` 作为文件和目录。新增同批完整路径校验，冲突时整体不入队，防止可预知的部分传输。
- 继续使用既有防路径穿越、符号链接、下载临时文件提交和云端条件写入逻辑。既有 OSS 版本化 Bucket 的禁止覆盖限制保持不变。
