## 4. 最小结构与关键契约

建议采用 `com.wlzn.oss` 下的 `config`、`model`、`service`、`ui`、必要时 `action` 五个包。下表中的文件名是建议新增路径，实施者可以根据实际职责合并小文件，避免为每个按钮新增一层抽象。

| 类区域 | 职责 | 关键约束 |
|---|---|---|
| `config/OssSettings` | application 级非敏感账号配置，稳定 UUID 识别账号 | State 不包含 AK ID/Secret/STS，不按可改显示名作为凭据主键 |
| `config/OssCredentialStore` | CredentialAttributes + PasswordSafe，读写账号秘密 | 新版平台要求后台且不持读锁访问；不在 createComponent/apply EDT 直接调用密钥库 |
| `config/OssSettingsConfigurable` | IDEA 设置页、账号增删和密钥编辑 | 后台加载凭据结果须绑定当前账号 UUID 与请求版本，防迟到回调填错账号 |
| `service/StorageClient`、`OssStorageClient`、`S3StorageClient` | 必要的小接口与两官方 SDK 适配，返回统一 Bucket/对象/分页/属性模型 | 不手写签名；接口只覆盖真实共同操作，差异通过能力或明确不支持表达，不用空成功伪装 |
| `service/TransferManager` | 项目生命周期任务、有界并发、取消与恢复 | 任务保存不可变账号/Endpoint/Bucket/key 快照；修改配置不会把已排队任务发往另一目标 |
| `ui/OssBrowserPanel` | Bucket 与对象列表、导航、工具栏、任务视图、操作确认 | EDT 只做界面工作；浏览响应按账号/Bucket/prefix/请求版本校验；旧请求不能覆盖新列表 |
| `ui/OssToolWindowFactory`、可选 `action/UploadToOssAction` | 工具窗口及项目树上传入口 | update 返回 BGT；上传前展示明确目标账号与路径 |

官方 Aliyun OSS Java SDK 与 AWS SDK for Java v2 S3 是必要的新生产依赖，邻近插件不存在等价能力。由实施者核实并锁定稳定版本。阿里优先 V4 签名并配置 Region；Amazon 使用同步 `S3Client` 与显式 `UrlConnectionHttpClient`，排除无需使用的 Netty/Apache 默认 HTTP 实现及 CRT 原生依赖，避免插件体积和加载冲突。不要打包 IDEA 已提供的 Kotlin 标准库/协程实现，不引入另外一套 UI 框架。

2026-10-28 多区域修订：V4 请求中的 Region 由 Bucket 真实位置自动解析，配置中的 Region/Endpoint 改为可选项；运行期签名需要 Region 不等于用户必须固定填写 Region。下文第 9 节为本轮修复依据，覆盖此前可能将配置视为固定单区域的表述。

传输方案有两个实际选择：A 为分别接入两 SDK 高层传输管理器，厂商封装成熟，但 AWS 高层 TransferManager 依赖异步 HTTP，增加 Netty/CRT 运行时；B 为在共同传输服务中使用两 SDK 的低层 multipart/Range 操作及一个小型 checkpoint 状态机。当前同步客户端约束下推荐 B，先以有限的文件级并发、单文件串行分片减少复杂度，不为速度增加第二套任务框架。该方案只编排官方请求，不自己实现签名协议；断点重放、取消和完成结果核对必须有测试，不能因为是“小状态机”而省略。调用本机 ossutil/aws CLI 会增加用户安装和进程凭据约束，暂不采用。

## 5. 数据、线程与失败处理

1. 账号普通元数据通过平台 PersistentStateComponent 保存；秘密由 PasswordSafe 按 UUID 隔离。删账号时清理其秘密；删除前告知相关未完成任务。
2. 读取/更新 PasswordSafe 放平台后台执行器，禁止在读动作内访问。设置页维护临时编辑缓冲，取消设置不能保存新凭据；Apply 后才持久化。
3. 浏览和 SDK 请求不持 PSI/VFS 读锁；UI 回调校验面板/项目存活及请求快照。关闭项目取消本项目任务、关闭相关流和客户端，不影响其他项目。
4. 上传下载用文件流及 SDK 断点能力，不用 `readBytes()` 把任意大文件全部载入内存。控制任务并发与 SDK 分片并发的乘积，避免连接数失控。
5. 断点文件保存在插件用户缓存目录，按 provider、账号 UUID、Endpoint、Region、Bucket、key、本地路径与文件指纹区分；不放项目源码目录，不含凭据或签名 URL。上传 checkpoint 保存 Upload ID、part size、完成 part 编号与 ETag，原子落盘；恢复前分页 ListParts 对账，不凭本地记录直接完成。源文件内容变化应拒绝旧断点，明确指纹依据，不能把 mtime 一项当作内容一致证明。下载断点绑定远端 ETag/大小与本地临时文件，恢复时加条件读取。
6. 取消/暂停、失败重试、清理碎片分别处理：暂停保留可恢复记录；取消是否清理远端 Part 由操作说明与确认决定，不能暗中删除别的上传记录。每片之间检查原子取消标记，请求内须有有限超时且可中断/可关闭流，不能依赖分片线程里没有上下文的 `ProgressManager.checkCanceled()`。完成 multipart 超时后结果未知，先 HEAD 对账，不能直接新建另一上传并覆盖。
7. 共用 multipart 参数要满足两个提供方的约束：非末片至少 5 MiB、每次最多 10,000 片；根据文件大小计算 part size，验证不超过提供方上限。空文件使用普通 put；恰好片大小、最后不足一片、超过片数上限均测试。单次复制大对象、元数据自复制同样受服务端 copy 限制，大于其单次上限时需 multipart copy 或明确提示限制，不能把失败当作已完成。
8. 目录上传/下载逐页或有界枚举。跳过或明确处理符号链接；远端 key 映射本地路径时拒绝绝对路径、`..`、分隔符歧义与已有 symlink 逃逸。目标临时文件完成后再替换，失败/取消保留可恢复状态。
9. 两种普通对象存储的目录都是 key 前缀，移动/重命名是 copy 后 delete；复制失败不删来源，复制成功但删除失败保留两份并反馈阶段。跨 Bucket/Region 的请求按 SDK 能力核实，不能拿当前目标 Endpoint 自动假设所有 Bucket 同地域。
10. 目录移动到自身后代、复制到自身、同目标重复任务须拒绝或明确处理。递归操作展示完整前缀，批量删除服务端部分失败要逐项反馈，不把 HTTP 200 一概算成功。
11. 文本编辑保存包含冲突检测与覆盖确认。自动重试不扩大为目标覆盖；网络超时后未知成功的写操作须重新读取核对，不能无条件重复 copy/delete。
12. 不记录凭据、签名 URL、请求头/完整 SDK 请求正文；正常错误以 operation、code、requestId 和必要目标信息排查。未知异常可保存安全堆栈，但先确认 SDK 异常文本不会泄露秘密。

## 9. 本轮修订：多区域自动路由与配置校验恢复

### 9.1 用户反馈与现状证据

用户明确指出，同一密钥可访问多个区域；Region 和 Endpoint 不应被强制绑定。另一个实际问题为：连接编辑框空字段点击 OK 后，校验失败使 OK 持续禁用，即使补全内容也不能提交。这两项均是对既有实现的修复，不改变凭据存储、远端对象权限或传输覆盖确认。

### 9.2 统一路由规则

1. 无 Endpoint、无 Region 是普通云账号的完整合法配置。打开账号时可列出有权限的 Bucket；也可指定 Bucket 直达，避免把 ListBuckets 权限作为前置。
2. Region 非空时先作为账号的发现/启动区域；对象请求以 Bucket 真实区域为准。Region 对应写入配置的值不得冒充每个 Bucket 的实际区域。
3. Endpoint 留空即进入官方端点自动路由；显式 Endpoint 保留原有手动模式，自定义、本地测试、专有网络/内网端点不被自动替换为公网。两项都已填写的旧 Profile 应继续沿原端点工作；字段清空后可进入标准自动发现路径。
4. 非空 Endpoint 仍沿现有严格 URI 校验；非空 Region 校验合法字符。标准区域端点可用确定规则推导 Region；自定义端点且探测无法确定签名区域时，在连接/操作中给出具体错误并允许补充，而不重新把所有账号配置的 Region 设为必填。
5. 自动发现只接受 SDK/服务端有明确语义的 Bucket 位置和规范 Endpoint；新建云客户端时由已验证 Region 构造官方地址。不能把任意服务端字符串作为携带账号凭据的跳转目标。手动配置的本地/自定义地址按原有显式授权配置处理。
6. 路由缓存键至少区分 provider、profile ID、配置 revision/配置身份、Bucket；缓存中不存密钥或签名 URL。刷新、配置变化和确定的区域重定向失配可失效。每个打开的适配器只关闭自己拥有的 SDK 客户端，不能让另一个请求关闭仍在使用的共享 client。
7. 最小新增 `RegionalStorageClient` 包装器覆盖共同接口的所有 Bucket 操作，按有效 Endpoint/Region 懒建并复用现有适配器，`StorageClient` 增加带默认实现的 `bucketRegion` 供 UI 和包装器查询，避免每个按钮自行路由。跨操作只缓存区域/端点元数据；不要为一项修复引入通用云路由框架。

### 9.3 阿里云 OSS 路由

- 使用可用的发现端点初始化只读发现客户端；`listBuckets()` 已带 Location 时优先种入本次缓存，否则按目标 Bucket 调用 `getBucketLocation`。将 `oss-cn-hangzhou` 等响应规范为 V4 所需的 `cn-hangzhou`，由真实地域构造标准 SDK Endpoint。
- 对明确的服务端区域/Endpoint 提示做受限纠正；须校验 Bucket 与域名，再只针对路由失败重新发起请求。不得把 `AccessDenied`、不存在对象、网络超时等普通失败统一解释为“换区重试”。
- V4 不允许仅改 Endpoint、不改签名 Region。位置解析、对象操作和签名链接应复用相同有效路由。
- GetBucketLocation 或 BucketInfo 等发现权限可能不具备；优先利用已有列表位置、服务端明确 Endpoint 信息。仍不能确定时明确反馈“无法自动确定该 Bucket 区域，可填写实际区域/端点”，不能声称账号无权限访问全部区域。
- 既有适配器的 copy 同时读取源对象 ACL/元数据并发复制请求；本轮只保留同区域 Bucket 复制，发现源目标不同区域时在复制前明确拒绝，源对象不发生删除。README/界面列出跨区域复制限制；多区域浏览和上传下载正常，不为该修复扩大为跨区域迁移实现。

### 9.4 Amazon S3 路由与预签名

- 标准 AWS 路径优先启用 SDK `crossRegionAccessEnabled(true)`，由官方 SDK 处理 Bucket 区域重定向与正确签名。启动区域使用用户提示或 SDK 所需的明确默认发现区域；该默认值不持久化、不限制可访问的其他 Bucket。
- 位置发现采用 `HeadBucket` 与确定的 `x-amz-bucket-region` 返回；本轮不引入额外 `GetBucketLocation` 权限。仅采用已验证为该目标 Bucket 返回的区域，不能把缺失 header 当作默认 `us-east-1` 的证明。
- S3Presigner 自身不会发送对象请求，也不能仅因为 S3Client 开启跨区域就认为预签区域会自动变更。生成链接前须确定目标 Bucket Region，并使用对应区域的 Presigner。自定义 Endpoint 和 pathStyle 的一致性仍须保留。
- HeadBucket 出错但带有确定区域 header 时可使用区域信息继续正确请求；没有位置时明确提示需填区域，不得默默签出启动区的错误链接。中国区/特殊分区若没有足够发现信息，也须清晰反馈，避免将商业区启动地址当成全部 AWS 分区支持的证明。
- 显式自定义 Endpoint（含本地协议测试）应继续按配置访问，避免 SDK 将请求自动重定向至真实 AWS 云端。区域自动校正和 HTTP 模拟测试必须分别覆盖标准云与显式端点路径。

### 9.5 传输与断点兼容

- `ConnectionProfile.routeIdentity()` 的现有序列化形状保持不变，继续表达 provider/用户 Endpoint/用户 Region/pathStyle；不要把探测出的 Bucket Region 写进 profile 后造成任务 revision 或 identity 变化。
- 新任务在执行时通过同一 Bucket 路由适配器进入正确区域。multipart begin/listParts/uploadPart/complete/abort 必须始终使用该 Bucket 的同一路由，取消清理也不能回到启动区域。
- 旧 Profile 未编辑时，其旧任务和 checkpoint 可继续恢复。用户主动清空/修改 Endpoint 或 Region 后，原有“配置身份变化需恢复原配置或新建任务”保护可以保留；不能为了自动模式而跳过身份检查，将旧 Upload ID 带到另一端点。
- 若后续希望让“手动标准端点改为自动发现”仍恢复旧任务，需要明确迁移并验证解析路由与旧实际目的地完全一致；本轮不凭推测改写 checkpoint 身份。
- 保留凭据 fingerprint、源文件哈希、ETag、下载临时文件和目标碰撞保护，不把区域修复扩大为传输状态机重构。

### 9.6 新建 Bucket 和 UI 校验

- 既有 Bucket 可自动发现区域；尚不存在的 Bucket 没有可发现的位置。将区域选择放进“新建 Bucket”对话框，仅在该写操作要求明确目标区域，保留服务端安全默认与用户确认。
- 连接状态可以显示“按 Bucket 自动选择区域”及当前 Bucket 的实际区域；不可把空字符串或启动区域作为已确认的目标区域展示。
- 已定位平台 DSL 的 continuousValidation 默认关闭。`ProfileDialog` 显式启用连续验证，错误关联名称、Region、Endpoint、AccessKey 或 Secret 等实际组件；修改后重新计算有效性并恢复 OK。本机 DialogWrapper 的 OK action 已核实会放行 withOKEnabled 错误，因此必填校验不使用该选项；无效输入仍阻断保存。验证和恢复仅在 EDT 上进行，不读取 PasswordSafe 或发起网络请求。
- 只补齐错误字段即可再次点击 OK；取消后重新打开仍正常。新增连接仍要求完整 AK ID + Secret，已有连接留空保留凭据、仅更新临时 Token、勾选移除 Token 等既有行为不变。
