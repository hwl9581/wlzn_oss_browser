# OSS Browser 1.0.7 本地验证记录

日期：2026-10-30。

## 问题与处理

版本控制已开启或暂停的 OSS Bucket 中，默认禁止覆盖上传会在提交阶段被插件拒绝，即使目标对象不存在也无法上传。此前的整桶拒绝逻辑不适合用户的使用方式。

用户已确认允许版本化 Bucket 使用普通上传，并保留上传前的同名检查。实现仅修改 AliyunStorageClient 的 PutObject 与 CompleteMultipartUpload 请求策略：

- 明确选择覆盖：继续普通上传。
- 未选择覆盖且 Bucket 未版本化：继续携带 `x-oss-forbid-overwrite: true`。
- 未选择覆盖且版本控制为 Enabled / Suspended：提交前再次 HEAD 检查目标。不存在时执行普通上传；目标已存在则停止，不发送写请求。
- 版本查询或 HEAD 权限失败直接报错，不自动降级。
- 没有修改覆盖对话框、任务记录、断点格式、S3 或下载逻辑；新目标不增加覆盖提示，已有同名文件仍可覆盖或跳过。

OSS 对 Enabled / Suspended Bucket 会忽略禁止覆盖请求头，因此最后 HEAD 与写入之间仍有并发窗口。开启版本控制时按服务端规则保留历史版本；暂停状态下 null 版本可能被替换。插件不修改 Bucket 的版本控制设置。

依据：[PutObject](https://help.aliyun.com/zh/oss/developer-reference/putobject)、[CompleteMultipartUpload](https://help.aliyun.com/zh/oss/developer-reference/completemultipartupload/)。
